AetioVision pipeline design

Medical codes or free text in. Synthetic X-ray / MRI / CT with anomaly out. MCP server first. Hexagonal: every step swappable. v4, implemented 2026-10-05 (changes in section 15).

1. Goal and scope

  • Baseline text-to-image models (MediSyn, RoentGen, MINIM) gave weak anomalies. Full-image generation hard to control.
  • New idea: start from real healthy image. Change only masked region. Anatomy stays real, only lesion synthetic.
  • Request = code triple: modality (DICOM) + body site (SNOMED CT) + malformation kind (SNOMED CT morphology). SNOMED finding codes and LOINC radiology codes accepted, resolved to triple automatically.
  • Steps: 1 text to codes (text endpoint only), resolve codes to triple, 2 pick healthy template, 3 pick or find anatomy mask, 4 inpaint.
  • Interface: MCP (stdio) + CLI. Old CLI kept in baselines/ as evaluation baseline.

In scope: 2D only (radiograph or single CT/MRI slice). Research use. Python 3.11+, uv.
Out of scope (now): 3D volumes, DICOM end-to-end, clinical use, lesion placement (#2), HTTP transport (#1), provenance marking (#3).

2. Medical codes

Same code systems as the German Medizininformatik-Initiative (MII) imaging profiles kerndatensatz-bildgebung: modality from DICOM, body site and laterality from SNOMED CT, findings from SNOMED CT clinical finding hierarchy.

Resolution rules

  1. Collect. Each input proposes slot values. finding: one role group (site, morphology) per group. procedure: modality + region / focus (focus wins, more specific) + laterality.
  2. Split laterality. Lateralized site ("Structure of left femur") becomes unlateralized parent + laterality.
  3. Merge. Two values for one slot: equal or one subsumes the other: keep more specific. Else CodeConflict. Site subsumption walks IS-A 116680003 + Part of 123005000.
  4. Pick role group. Finding with several groups: keep groups that roll up to supported set. One left: take it. Else AmbiguousCode listing groups.
  5. Fill gaps (D19). Missing slot with exactly one supported value given other slots: fill, record in assumptions. Else UnsupportedRequest with candidates.
  6. Roll up. requested triple = most specific codes. supported triple = nearest ancestor-or-self in supported set ("Transverse fracture" to "Fracture", "Femoral shaft" to shaft mask). None: UnsupportedRequest with nearest candidates.

requested feeds the inpainter prompt (specific display names). supported feeds catalog, mask lookup, inpainter choice.

Import script

uv run aetio import-terminology --snomed DIR --loinc DIR writes data/terminology.db (SQLite, gitignored). Only rows needed:

sct_isa       (child, parent)                              -- inferred 116680003 IS-A

  • Ancestors: recursive CTE on sct_isa (+ sct_attr type Part of for sites). No closure table needed.
  • Import prints coverage: share of radiology region / focus parts with SNOMED mapping. Unmapped part at runtime: UnknownCode with part name (no LLM fallback, by decision).

Hand-written, only these

  • SNOMED constants: 3 hierarchy roots, 5 attribute ids (listed above).
  • LOINC modality part to DICOM: {"XR": "DX", "CT": "CT", "MR": "MR"}. 3 entries, LOINC does not map modality parts to DICOM verify in PartRelatedCodeMapping.
  • Inpainter capabilities: abstract SNOMED codes each adapter handles, e.g. (DX, bone structure, Fracture). Capability list, not mapping table.

4. Request DTO and domain types

API edge: pydantic (MCP tool args, CLI flags)

# api/dto.py
DCM   = Annotated[str, StringConstraints(pattern=r"^DCM:[A-Z]{2}$")]
SCT   = Annotated[str, StringConstraints(pattern=r"^SCT:\d{6,18}$")]
LOINC = Annotated[str, StringConstraints(pattern=r"^LOINC:\d{1,7}-\d$")]

class GenerateFromCodes(BaseModel):
    """Give a triple, a SNOMED finding, a LOINC procedure, or a mix. Missing slots
    are filled from the other codes or inferred when only one supported value fits."""
    model_config = ConfigDict(extra="forbid")

    # canonical triple, each slot optional when another code supplies it
    modality: DCM | None = None          # DCM:DX
    body_site: SCT | None = None         # SNOMED body structure
    morphology: SCT | None = None        # SNOMED morphologic abnormality, the malformation kind
    laterality: SCT | None = None        # SCT:7771000 left, SCT:24028007 right, SCT:51440002 bilateral

    # pre-coordinated sources, resolved to triple slots
    finding: SCT | None = None           # clinical finding / disorder, e.g. SCT:71620000 Fracture of femur
    procedure: LOINC | None = None       # radiology term, e.g. LOINC:24725-4 CT Head

    instructions: str = Field("", max_length=2000)   # free detail for inpainter prompt
    seed: int | None = Field(None, ge=0)

    @model_validator(mode="after")
    def _some_code(self) -> "GenerateFromCodes":
        if not any((self.modality, self.body_site, self.morphology, self.finding, self.procedure)):
            raise ValueError("give a triple, a SNOMED finding, a LOINC procedure, or a mix")
        return self

    def to_domain(self) -> CodeRequest: ...          # Code.parse on every field
  • Regex checks shape only. Existence and hierarchy (body structure vs morphology vs finding) checked by resolver against terminology.db.
  • Text endpoint: extractor returns same CodeRequest, triple fields limited to supported set (enum in LLM schema), rest of text in instructions.

Core: frozen dataclasses

# domain/codes.py
@dataclass(frozen=True)
class Code:
    system: Literal["DCM", "SCT", "LOINC"]
    code: str
    display: str = field(default="", compare=False)

    @classmethod
    def parse(cls, curie: str) -> "Code": ...      # "SCT:71341001" -> Code("SCT", "71341001")

    def __str__(self) -> str:
        return f"{self.system}:{self.code}"

@dataclass(frozen=True)
class Triple:
    modality: Code        # DCM
    body_site: Code       # SCT body structure
    morphology: Code      # SCT morphologic abnormality


# domain/request.py
@dataclass(frozen=True)
class CodeRequest:                         # what client sent, unresolved
    modality: Code | None = None
    body_site: Code | None = None
    morphology: Code | None = None
    laterality: Code | None = None
    finding: Code | None = None
    procedure: Code | None = None
    instructions: str = ""
    seed: int | None = None

@dataclass(frozen=True)
class ResolvedRequest:
    requested: Triple                      # most specific codes from input, for prompt
    supported: Triple                      # nearest supported ancestors, for catalog / mask / inpainter
    laterality: Code | None
    instructions: str
    seed: int
    sources: dict[str, str]                # slot -> origin, e.g. "body_site": "finding SCT:71620000"
    assumptions: list[str]                 # slots filled by inference (D19)

Errors in domain/errors.py: PipelineError base, InvalidCode, UnknownCode, CodeConflict, AmbiguousCode, UnsupportedRequest (carries candidates), NoTemplate, MaskingFailed, InpaintFailed. MCP maps to isError, CLI to exit code.

Import rules

  • domain/ imports nothing from project.
  • pipeline/ imports domain/ only. Never adapters.
  • Adapter imports pipeline.ports, domain/, shared/, utils/. Never other step dirs.
  • api/ imports pipeline/ + domain/, gets Pipeline from main.py.
  • main.py only place importing concrete adapters, lazily per env value.
  • Model client code lives in adapter using it. Moves to shared/ when second adapter needs it.

8. Ports and pipeline

# pipeline/ports.py
class Terminology(Protocol):
    def lookup(self, code: Code) -> Code: ...                               # display filled, UnknownCode if absent
    def ancestors(self, code: Code) -> list[Code]: ...                      # self first, nearest first (IS-A + Part of)
    def finding_groups(self, finding: Code) -> list[tuple[Code, Code]]: ... # [(site, morphology)] per role group
    def split_laterality(self, site: Code) -> tuple[Code, Code | None]: ... # left femur -> (femur, left)
    def procedure_parts(self, loinc: Code) -> ProcedureParts: ...           # modality, site, laterality

class CodeExtractor(Protocol):
    def extract(self, text: str, supported: SupportedSet) -> CodeRequest: ...

class TemplateCatalog(Protocol):
    def coverage(self) -> set[tuple[Code, Code]]: ...                       # (modality, mask body site)
    def select(self, req: ResolvedRequest) -> Template: ...

class AnatomyMasker(Protocol):
    def mask(self, template: Template, site: Code) -> Mask: ...

class Inpainter(Protocol):
    def capabilities(self) -> set[Triple]: ...                              # abstract codes: (DX, bone structure, Fracture)
    def inpaint(self, template: Template, mask: Mask, req: ResolvedRequest) -> MedicalImage: ...


# pipeline/pipeline.py
@dataclass
class Pipeline:
    terminology: Terminology
    extractor: CodeExtractor
    catalog: TemplateCatalog
    masker: AnatomyMasker
    inpainters: list[Inpainter]                  # order = priority (D27)

    def __post_init__(self) -> None:
        self.supported = build_supported(self.catalog.coverage(), self.inpainters, self.terminology)

    def from_text(self, text: str, seed: int | None = None) -> Result:
        return self.from_codes(replace(self.extractor.extract(text, self.supported), seed=seed))

    def from_codes(self, req: CodeRequest) -> Result:
        resolved = resolve(req, self.terminology, self.supported)
        template = self.catalog.select(resolved)
        mask = self.masker.mask(template, resolved.supported.body_site)
        image = self.supported.inpainter_for(resolved.supported).inpaint(template, mask, resolved)
        return Result(resolved, template, mask, image)


# pipeline/supported.py
def build_supported(coverage, inpainters, terminology) -> SupportedSet:
    """Triple (m, site, morph) supported when a template has a mask for (m, site) and an
    inpainter capability (m, scope, morph) has scope among site's ancestors. First inpainter wins."""
  • Resolution and supported set = pure functions over Terminology. Tested with in-memory fake terminology, no DB.
  • Adapters load models lazily on first inpaint() / mask(). capabilities() cheap.
  • Inpainter builds own prompt: requested display names + laterality + instructions.
  • Pixels float32 in [0, 1], windowing once at template ingestion (D17).

# src/aetiovision/main.py  (only file importing concrete adapters)
def build() -> Pipeline:
    env = os.environ
    data = Path(env.get("AETIO_DATA", "data"))
    return Pipeline(
        terminology=SqliteTerminology(data / "terminology.db"),
        extractor=make_extractor(env.get("AETIO_EXTRACTOR", "rules")),
        catalog=SqliteCatalog(data / "catalog.db"),
        masker=PredefinedMasker(fallback=make_mask_fallback(env.get("AETIO_MASK_FALLBACK", "none"))),
        inpainters=[make_inpainter(n.strip()) for n in env.get("AETIO_INPAINTERS", "procedural").split(",")],
    )

def make_inpainter(name: str) -> Inpainter:
    match name:
        case "procedural":
            from aetiovision.inpainting.procedural import ProceduralInpainter
            return ProceduralInpainter()
        case "roentgen":                                   # torch imported only here
            from aetiovision.inpainting.roentgen import RoentgenInpainter
            return RoentgenInpainter()
    raise SystemExit(f"AETIO_INPAINTERS: unknown inpainter {name!r}")

13. Risks

  • Finding without morphology. Some SNOMED findings have no Associated morphology (pneumothorax, effusion possible). Client then must send morphology. Check per target in M1.
  • LOINC part mapping gaps. Not every region part has SNOMED mapping. Import reports coverage; unmapped = typed error.
  • SNOMED license. BfArM affiliate license needed before import (TUM may already hold one). Terminology DB never in git.
  • Codes typed from memory. Verify in browsers. Data test checks catalog codes exist with right hierarchy.
  • MSK X-ray quality. No open fracture inpainter. Procedural first, LoRA next.
  • Whole sub-part repainted. No placement in v1 (D24). Keep sub-part masks small; placement in #2.
  • Model / data licenses. BiomedParse NC-SA, RoentGen via MIMIC, BraTS NC. Research only.
